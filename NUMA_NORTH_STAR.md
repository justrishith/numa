# NUMA North Star

> Canonical source of truth for NUMA's product purpose and long-term direction.

**Status:** Active
**Owner:** NUMA project

## Product definition

NUMA is one local agent brain that helps operate, understand, and improve the user's digital laboratory.

NUMA is not a collection of unrelated assistants. Poni, the desktop dashboard, voice, and Telegram are interfaces to the same NUMA brain.

## Core principles

1. One brain, one identity, one memory model.
2. Fast deterministic actions should not require slow reasoning.
3. NUMA must verify meaningful actions before claiming success.
4. Computer control must be powerful, visible, permissioned, and interruptible.
5. GBrain is durable knowledge, not a second agent.
6. The computer is a laboratory for projects, experiments, routines, and business work.
7. The UI and UX are first-class product features.
8. Failures must be honest, understandable, and recoverable.

## Interface roles

- **Poni:** native Windows shell, notch, microphone, audio, hotkeys, overlays, and emergency stop.
- **NUMA dashboard:** command center, projects, lab, memory, activity, permissions, and settings.
- **Chrome extension:** access to the user's existing Chrome session and signed-in websites.
- **Telegram:** optional remote interface to the same NUMA sessions.
- **GBrain:** long-term knowledge, entities, project context, notes, decisions, and durable memory.

## Business-partner behavior

NUMA maintains continuity across goals, projects, tasks, routines, experiments, decisions, and reviews. It should help identify blockers, preserve context, prepare next actions, and support research and execution without pretending to be an autonomous owner of decisions.

## Brand direction

NUMA is represented by the Electric Night Butterfly: a refined, geometric, cinematic butterfly with dark translucent wings, violet and cyan edge lighting, a luminous core, circuit-inspired wing patterns, and subtle N-shaped symmetry.

The product should feel calm, precise, intelligent, beautiful, and alive—not like a generic chatbot or dashboard template.

## Success metrics

- Zero unwanted computer actions during idle testing.
- Simple commands complete in under two seconds where the target system permits it.
- Critical actions require explicit approval.
- Verified action claims reach 100%.
- Emergency stop is available and fast.
- Users can inspect and correct durable memory.
- The interface remains understandable during execution, failure, and recovery.
